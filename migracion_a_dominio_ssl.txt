# - Dominio apuntando a la IP del servidor
# - Acceso SSH al servidor

## 🚀 MIGRACIÓN PASO A PASO

### PASO 1: PREPARAR NGINX HOST (SIN ROMPER DOCKER)
```bash
# Instalar Nginx en Ubuntu (NO afecta Docker)
sudo apt update
sudo apt install nginx certbot python3-certbot-nginx -y

# Detener Nginx temporalmente (no afecta Docker)
sudo systemctl stop nginx
```

### PASO 2: CAMBIAR PUERTO DOCKER (SIN DOWNTIME)
```bash
cd /var/www/clinica

# Backup del docker-compose actual
cp docker-compose.yml docker-compose.yml.backup

# Cambiar puerto de 80:80 a 8080:80
sed -i 's/"80:80"/"8080:80"/g' docker-compose.yml

# Verificar el cambio
grep -n "8080:80" docker-compose.yml

# Aplicar cambio (sin rebuild para ser más rápido)
docker-compose stop nginx
docker-compose up -d nginx
```

### PASO 3: VERIFICAR QUE DOCKER FUNCIONA EN PUERTO 8080
```bash
# Test interno (debe funcionar)
curl -I http://localhost:8080

# Si no funciona, rollback:
# cp docker-compose.yml.backup docker-compose.yml
# docker-compose up -d
```

### PASO 4: CONFIGURAR NGINX REVERSE PROXY
```bash
# Crear configuración inicial (solo HTTP)
sudo tee /etc/nginx/sites-available/clinica << 'EOF'
server {
    listen 80;
    server_name midominio.com www.midominio.com;

    # Permitir validación Let's Encrypt
    location /.well-known/acme-challenge/ {
        root /var/www/html;
    }

    # Proxy hacia Docker
    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-Host $server_name;

        # Timeouts
        proxy_connect_timeout 60s;
        proxy_send_timeout 60s;
        proxy_read_timeout 60s;
    }

    # Logs
    access_log /var/log/nginx/clinica_access.log;
    error_log /var/log/nginx/clinica_error.log;
}
EOF
```

### PASO 5: ACTIVAR CONFIGURACIÓN NGINX
```bash
# Habilitar sitio
sudo ln -s /etc/nginx/sites-available/clinica /etc/nginx/sites-enabled/

# Deshabilitar sitio default
sudo rm -f /etc/nginx/sites-enabled/default

# Verificar configuración
sudo nginx -t

# Si hay errores, revisar configuración
# sudo nano /etc/nginx/sites-available/clinica
```

### PASO 6: INICIAR NGINX Y PROBAR
```bash
# Crear directorio para validación SSL
sudo mkdir -p /var/www/html

# Iniciar Nginx
sudo systemctl start nginx
sudo systemctl enable nginx

# Test con dominio (sin SSL aún)
curl -I http://midominio.com
```

### PASO 7: CONFIGURAR FIREWALL PARA SSL
```bash
# Permitir HTTPS
sudo ufw allow 443/tcp

# Verificar reglas
sudo ufw status
```

### PASO 8: OBTENER CERTIFICADO SSL
```bash
# Obtener certificado (reemplazar midominio.com)
sudo certbot --nginx -d midominio.com -d www.midominio.com --email admin@midominio.com --agree-tos --non-interactive

# Verificar que se instaló correctamente
sudo certbot certificates
```

### PASO 9: ACTUALIZAR LARAVEL PARA HTTPS
```bash
# Actualizar URL en .env
docker-compose exec php sed -i 's|APP_URL=.*|APP_URL=https://midominio.com|g' .env

# Limpiar caché de configuración
docker-compose exec php php artisan config:clear
docker-compose exec php php artisan optimize
```

### PASO 10: CONFIGURAR RENOVACIÓN AUTOMÁTICA
```bash
# Agregar renovación automática a crontab
(crontab -l 2>/dev/null; echo "0 12 * * * /usr/bin/certbot renew --quiet && systemctl reload nginx") | crontab -

# Verificar crontab
crontab -l
```

## 🔄 ROLLBACK (Si algo sale mal)

### ROLLBACK COMPLETO:
```bash
# 1. Restaurar puerto Docker original
cd /var/www/clinica
cp docker-compose.yml.backup docker-compose.yml
docker-compose down
docker-compose up -d

# 2. Deshabilitar Nginx
sudo systemctl stop nginx
sudo systemctl disable nginx

# 3. La aplicación volverá a funcionar en http://TU_IP
```

### ROLLBACK PARCIAL (mantener dominio sin SSL):
```bash
# Eliminar SSL pero mantener dominio
sudo certbot delete --cert-name midominio.com

# Editar configuración Nginx para quitar SSL
sudo nano /etc/nginx/sites-available/clinica
# (quitar configuración SSL, dejar solo HTTP)

sudo systemctl reload nginx
```

### Backup mejorado:
```bash
# Script de backup que incluye configuración
#!/bin/bash
DATE=$(date +%Y%m%d_%H%M%S)
BACKUP_DIR="/backups/clinica"

mkdir -p $BACKUP_DIR

# Backup BD
docker-compose exec -T mysql mysqldump -u root -proot2025 clinica | gzip > $BACKUP_DIR/db_$DATE.sql.gz

# Backup configuración Nginx
sudo cp /etc/nginx/sites-available/clinica $BACKUP_DIR/nginx_config_$DATE

# Backup .env
cp .env $BACKUP_DIR/env_$DATE

echo "Backup completado: $DATE"
```

## 🆘 TROUBLESHOOTING

### Problema: Nginx no inicia
```bash
sudo nginx -t
sudo systemctl status nginx
sudo journalctl -u nginx --since "5 minutes ago"
```

### Problema: SSL no funciona
```bash
sudo certbot certificates
sudo certbot renew --dry-run
openssl s_client -connect midominio.com:443
```

### Problema: Docker no responde
```bash
docker-compose logs
curl -I http://localhost:8080
docker-compose restart
```

### Problema: Loops de redirección
```bash
# Verificar configuración proxy en Nginx
sudo nginx -T | grep proxy_set_header
# Asegurar que X-Forwarded-Proto esté configurado
```

## 📝 ARQUITECTURA FINAL

```
Internet → Nginx (Ubuntu) → Docker Nginx → PHP-FPM → MySQL
         ↑ Puerto 80/443   ↑ Puerto 8080
       SSL/Dominio      HTTP interno
```

## 🎯 BENEFICIOS DE ESTA ARQUITECTURA

✅ **Cero downtime**: Docker sigue funcionando mientras configuras Nginx
✅ **Rollback fácil**: Puedes volver a IP en cualquier momento
✅ **SSL nativo**: Mejor performance que SSL dentro de Docker
✅ **Mantenimiento independiente**: Nginx y Docker se gestionan por separado
✅ **Escalabilidad**: Fácil agregar load balancing más tarde
